When a change takes effect

The token is handed to a container when it is created, so models already running keep the environment they started with. That does not matter for weights that are already on disk — but if you set a token so a gated model can download, deploy that model after saving it here, not before.

{{/* PLAINTEXT ON DISK, SAID PLAINLY. This is the one panel on this page whose setting controls how long something sensitive sits around rather than how a download behaves - the copy has to carry that weight rather than read like every other retention knob. */}}

Request log

Every /v1/chat/completions request is written to this node's disk — who sent it and the request exactly as received, prompts included. It is an audit trail, not a cache: there is no redaction and no size cap, only the retention window below deciding how long anything lasts.

Checked hourly; a file is removed only once every request in it is older than this window. 0 keeps just today's traffic. Today's file is never removed by its own day's cleanup, so the window is never emptied out from under an in-flight write.
